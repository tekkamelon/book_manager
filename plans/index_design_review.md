# トップページ デザインレビュー

対象: `html/index.html` (配色・余白・コンポーネントは `css/style.css`)

参照:

- 現行画面のスクリーンショット (ダークテーマ)
- 旧トップ (`img/screenshot_dark.png` / `img/screenshot_light.png`)
- 関連ページ (`list.html`, `add.html`, `confirm.html`, `settings.html`)
- 関連スクリプト (`js/index.js`)

---

## 1. 総評

書斎や紙の本を連想させる暖色のセリフ基調で、蔵書管理という用途に世界観がよく合っている。旧トップの「全幅ボタンを並べたランチャー」から、説明付きの機能一覧とタブ型ナビへ進んだ点は情報量として前進している。

一方で、同じ行き先がタブとカード内に二重に現れ、ラベルも揃っていない。見た目の完成度に対して、情報設計とセマンティクスが追いついていない。

---

## 2. 良い点

### 2.1 世界観と配色

- 茶・生成り・金茶のパレットが紙・革装丁・インクを想起させ、蔵書管理の用途と一致している
- `light-dark()` と `color-scheme: light dark` でライト/ダークを変数一箇所で切り替えられる
- 背景の放射グラデーションとカードの影が、派手すぎない奥行きを出している
- アクセント色 (`--accent`) を見出しとボタンに限定しており、画面が落ち着いている

### 2.2 タイポグラフィと階層

- `"Noto Serif", "Georgia", serif` が書籍アプリらしい印象を支えている
- `h1` の字間 (`letter-spacing: 0.05em`) と中央揃えが、タイトルとしての格を出している
- 導入文 `.page-intro` を `--text-secondary` で一段下げ、タイトル > 説明 > 操作、の順が読み取れる
- 本文の行間 `1.8` は日本語の長文にも余裕がある

### 2.3 機能カードの見せ方

- 各機能が「見出し + 一文説明 + 操作」になっており、旧デザインのラベルだけの全幅ボタンより中身が伝わる
- 説明文が短く、何をする画面かがカード内で完結する
- 項目間の細い区切り線と左右レイアウト (説明 | ボタン) で、視線が縦に流れやすい
- ボタンのホバーでわずかに浮く動きがあり、操作対象だと分かりやすい

### 2.4 タブ型ナビゲーション

- ブラウザのタブに似せた形状で、現在地 (`aria-current="page"`) が視覚的に分かる
- 選択中タブの下線をカードし、直下のカードとつなげる処理 (`nav + .card`) が丁寧
- ホバー時に背景と文字色が変わるため、未選択タブもリンクだと認識しやすい
- 他ページとナビ構成が揃っており、サイト内の移動モデルが一貫している

### 2.5 レスポンシブの下地

- `viewport` メタがある
- 600px 以下でカード内を縦積みにし、ボタンを全幅にしている (タッチしやすい)
- ナビは横スクロール (`overflow-x: auto`) にして、長いラベルを無理に折っていない

### 2.6 アクセシビリティの基礎

- `html lang="ja"`
- 現在ページを `aria-current="page"` で示している
- 編集環境のボタンに `type="button"` があり、誤 submit を防いでいる
- `button` / `input[type="submit"]` にフォーカスリング (`outline-offset: 3px`) がある
- 機能ブロックに `h2` を使っており、見出し階層の骨格はある

### 2.7 余白とコンテナ

- `.container` の `max-width: 720px` で行長が読みやすい
- カードの角丸 12px・内側余白 2rem が、項目数の少ないトップに対して窮屈でない

## 3. 改善すべき点

### 3.1 情報設計: 導線の重複

トップは「ランチャー」なのに、タブとカードがほぼ同じ行き先を繰り返している。

| タブ | カード内 | 実際の行き先 |
| --- | --- | --- |
| トップ | (なし) | `index.html` |
| 蔵書一覧 | 蔵書一覧 | `list.html` |
| 書籍追加・データ検索 | 書籍追加・データ検索 | `add.html` |
| 編集 | 編集環境 | タブは `confirm.html`、カードは JS 経由で code-server |
| 設定 | 設定 | `settings.html` |

問題:

- 同じ操作が二箇所にあり、トップ専用の価値 (説明文) がタブと競合する
- 「編集」タブは確認ページそのものへ飛ぶ。URL なしで開くと「外部サイトに移動しようとしています」だけが表示され、編集作業の入口になっていない
- 「編集」と「編集環境」は別名なのに、利用者には同一機能に見える
- 主作業 (一覧・追加) と管理作業 (編集環境・設定) が同じ視覚的重さで並んでいる

改善案:

- タブはサイト共通の現在地表示に徹し、トップのカードは主作業 2 つを大きく、設定系は一段下げる
- ナビの「編集」は外すか、「編集環境」に改名し、未設定時は設定ページへ誘導する
- カード全体 (行全体) をクリック可能にし、右端の「開く」は補助にする

### 3.2 ラベルと用語の揺れ

- 画面タイトルは英語 `Book Manager`、導入・機能名は日本語、フッターは `Links` / `Reference` / `GitHub Repository`
- ナビ「編集」とカード「編集環境」、`confirm.html` の見出し「外部リンクの確認」が三通りある
- ボタン文言がすべて「開く」で、スクリーンリーダーでは「開く、開く、開く、開く」になる
- 「書籍追加・データ検索」はタブ幅に対して長く、何と何ができるのかが一語で分からない

改善案:

- UI 文言は日本語に揃える (例: 関連リンク、リポジトリ)
- ボタンは「一覧を見る」「ISBN で追加」など、行き先が分かる動詞にする
- 外部へ出る操作だけ「外部で開く」など区別する

### 3.3 セマンティクスとマークアップ

現行の骨格:

```html
<div class="container">
  <h1>...</h1>
  <nav>...</nav>
  <div class="card">...</div>
  <script>...</script>
</div>
<footer>...</footer>
```

問題:

- `<main>` がなく、主要コンテンツのランドマークがない
- `<nav>` に `aria-label` がない (ページ内にナビが複数ある将来に弱い)
- 機能 3 項目は `<section>`、編集環境だけ `<div class="editor-link">` で、見た目は同じなのに構造が違う
- 機能一覧はリストでもリンク集でもなく、`div` の直列である
- `script` が `.container` 内にあり、フッターだけコンテナ外。フッター上の罫線がカードより横に長く、幅が揃わない
- フッター見出しが `h3` で、直前の `h2` の下位に見える (ページ全体の関連リンクとしては `h2` が妥当)
- 行内の説明とボタンが関連づく `aria-labelledby` / `aria-describedby` がない

改善案:

- `<header>` + `<nav aria-label="メイン">` + `<main>` + `<footer>` に分ける
- 機能行はすべて `section` (または `ul` / `li`) に揃える
- フッターも `.container` と同じ幅に乗せる

### 3.4 視覚的な優先度

- 4 つの「開く」が同色・同サイズで、最初に押すべき操作が分からない
- アイコンや書影がなく、文字だけの行が続く。蔵書アプリなのに本の気配がタイトル書体以外にない
- トップに冊数・最近追加した本がなく、空のランチャーで終わっている
- 旧デザインは「大きなボタンが仕事」で迷いにくかった。現行は説明が増えた分、一操作あたりのコストも増えている

改善案:

- 蔵書一覧・追加を primary、設定系を text link または小さい secondary にする
- 可能なら最近の登録や件数をトップに出す
- 機能行に小さなアイコン (棚、ISBN、鉛筆、歯車) を足すと走査が速くなる

### 3.5 インタラクションとアクセシビリティ

- `.button` (アンカー) に `button:focus` 相当のフォーカススタイルが当たっていない。キーボード操作で「開く」リンクの視認が弱い
- `.button:active` も未定義で、`button` だけ押下時に沈む
- 一般 `a:hover` の下線が `.button:hover` にも付く可能性がある
- フォント `"Noto Serif"` を CSS で指定しているが、`@font-face` も外部配信もなく、未導入環境では Georgia に落ちる
- モバイルのタブ横スクロールに、続きがあることを示すフェードやスクロールヒントがない
- 編集環境は未設定時に `alert()` だけ。設定画面への導線がない
- 編集環境が外部ツールだと、ボタン見た目からは分からない
- スキップリンクがない

コントラスト (ダーク、カード背景 `#3d3833`):

- 本文 `#e8e0d4`: 問題になりにくい
- アクセント見出し `#c4a77d`: おおよそ 5:1 前後で AA ぎりぎり。細字の `h2` だと環境によって足りない
- 未選択タブ `#b8aead` はさらに落ちるので、タブが「薄い装飾」に見えやすい

### 3.6 フッターの役割

- GitHub が `tree/experimental` 固定で、利用者が見る既定ブランチとずれる可能性がある
- `urldecode` の参照は開発者向けで、蔵書の利用者には意味が薄い
- トップ以外にフッターがなく、サイトの締めがページによって違う

改善案:

- 利用者向けリンクと開発者向けリンクを分けるか、後者は README 側へ移す
- 置くなら全ページ共通にする

### 3.7 CSS 上の脆さ

- `h1` の下マージン 2rem を `.page-intro` の負マージン `-1.2rem` で打ち消しており、見出しを変えると崩れる
- `.feature-item` と `.editor-link` に同じ見た目を二重定義している
- フォーカスリングが `button` / `submit` 限定で、`.button` とトグル、ナビリンクがバラバラ
- ライト/ダークは OS 連動のみ。設定画面にテーマ固定がない (このアプリを投影や共用端末で使う場合に不便)

## 4. 旧デザインとの比較

| 観点 | 旧トップ (スクリーンショット) | 現行トップ |
| --- | --- | --- |
| 第一印象 | 大きなボタン 4 つ。すぐ押せる | 説明付き。落ち着いて読める |
| 現在地 | ナビなし | タブで分かる |
| 機能の意味 | ラベル頼み | 一文で補足される |
| 迷いにくさ | 選択肢が少ない | タブとカードで重複 |
| 主作業の強調 | 全ボタンが同等 | 全ボタンが同等のまま |
| 世界観 | 既に暖色 | タブ接続や導入文で一段洗練 |

残すべきなのは現行の世界観・説明文・タブの現在地表示。戻すべきなのは旧デザインの「押す場所が一つで大きい」こと。

## 5. 改善の優先度

### P1 (情報設計・誤解)

- ナビ「編集」とカード「編集環境」の行き先・名称を揃える。未設定の `confirm.html` を通常タブにしない
- ボタン文言を行き先が分かる語にする
- 主作業 (一覧・追加) と管理 (編集環境・設定) の視覚的優先度を分ける

### P2 (マークアップと操作)

- `<main>` / `<header>` / `<footer>` のランドマーク
- 機能行のマークアップを揃える (`section` またはリスト)
- `.button` にもフォーカス・アクティブスタイルを当てる
- 行全体をクリック可能にする
- 編集環境の失敗時は `alert()` ではなく設定への案内にする

### P3 (見た目の完成度)

- `Noto Serif` を実際に読み込む
- タブ横スクロールのヒント
- フッター幅をカードと揃える。文言を日本語化
- 負マージンをやめ、タイトル周りの余白を正の値で組む
- アクセント色のコントラストを AA に余裕を持たせる
- 件数や最近の本など、トップならではの情報を足す

## 6. このまま残してよい判断

- 暖色のセリフ基調と `light-dark()` のトークン設計
- タブとカードを視覚的につなぐ処理
- 機能ごとの短い説明文
- モバイルでボタンを全幅にする方針
- `aria-current="page"` による現在地

「本棚の前に立って、目的の棚を選ぶ」感覚は現行で既に出ている。次は棚札 (ラベル) と動線を矛盾なくし、よく使う棚だけを手前に出す段階である。
