# スマートフォンカメラによるISBNバーコード読取(iOS想定)

## 概要

書籍追加と蔵書検索で、iPhone(Safari)の背面カメラから書籍JAN(EAN-13)を読み、ISBN入力欄または検索欄へセットする。
サーバー側CGIはISBN文字列を既に受け取れるため、デコードはブラウザ側JavaScriptで完結させる。

主対象は iOS Safari。`BarcodeDetector` は WebKit 未実装のため本線にしない。
Chrome 等では将来的にネイティブAPIを使ってもよいが、初回実装では単一路線(JS/WASMデコーダ)に揃える。

## 前提

- 既存の追加フロー: `html/add.html` の `#isbn` を POST し `cgi-bin/add.cgi` が `bm_search` 等で取得する
- 既存の検索フロー: `html/list.html` の `#q` を `js/list.js` の `filterResult` がクライアント側で絞り込む
- `html/search.html` と `cgi-bin/search.cgi` は非推奨。読取UIは載せない
- カメラAPIはセキュアコンテキスト必須(HTTPS または localhost)
- 現在の `cgi_server.py` は HTTP(ポート8000)。iPhone実機の LAN IP では `getUserMedia` が拒否されやすい
- 書籍バーコードは上段がISBN(978/979始まりのEAN-13)、下段が価格コード(192始まり等)であることが多い
- 手入力は残す。読取は補助機能とする
- プロジェクトルート: `/home/tekkamelon/Documents/github/book_manager`

## 方針

### デコーダ

- 本線: ZXing 系のブラウザライブラリ(html5-qrcode、または `@zxing/browser` / WASM版)
- iOS では `BarcodeDetector` が使えないため、最初からライブラリ経路のみにする
- 対象フォーマットは EAN-13 を優先。QR や Code128 は無効化または無視する
- ライブラリは CDN ではなくリポジトリ内(`js/vendor/` 等)に置く。オフライン・自己ホスト前提に合わせる

### カメラ

- 開始はボタンタップ(ユーザー操作)からのみ。ページロード時の自動起動はしない
- `facingMode: "environment"` で背面カメラを指定する
- `video` には `playsinline` を付ける(iOSで全画面再生に逃げるのを防ぐ)
- 1回成功したら直ちにストリームを止める。連続読取はしない(発熱・誤連続入力対策)
- 権限拒否・起動失敗時はメッセージを出し、手入力へ誘導する

### ISBN正規化

読取文字列に対して次を順に行う。

1. ハイフン・空白を除去する
2. 数字のみ13桁であること
3. 先頭が `978` または `979` であること(価格コードを捨てる)
4. 任意: 既存の `isbn_checker` 相当のチェックデジット検証をJSでも行う
5. 条件を満たさなければプレビューを継続し、満たしたら入力欄へセットして停止する

ISBN-10 の旧バーコードは初回対象外とする。手入力で足りる。

### HTTPS

iOS実機で使うには次のいずれかが必要。本機能のコードとは別件として扱うが、検証ブロッカーである。

- リバースプロキシで HTTPS 終端する
- 開発時のみ HTTPS トンネルを使う
- 実機検証用の手順を README または本計画のテスト節に書く

HTTP のまま UI だけ足しても、実機 Safari ではカメラが開かない可能性が高い。

## 手順

### 1. 共通モジュール `js/barcode.js` を新規作成

画面ごとの重複を避ける。公開APIは小さくする。

想定インタフェース:

- `mountBarcodeReader(options)`
  - `trigger`: 開始ボタン要素
  - `preview`: プレビュー用コンテナ
  - `onSuccess(isbn)`: 正規化済みISBNを渡す
  - `onError(message)`: 権限拒否・非対応・起動失敗
- 停止処理(`stop`)を内部で持つ。成功時とページ離脱時に呼ぶ
- ページ非表示(`visibilitychange` / `pagehide`)でも止める

責務の分割:

- カメラ起動・停止: ライブラリまたは `getUserMedia`
- デコード: ライブラリ
- ISBN判定: 自前関数 `normalizeIsbn(raw)` (単体でテストしやすい形)

フォールバック(任意だが iOS では推奨):

- `<input type="file" accept="image/*" capture="environment">` で静止画を撮り、同じデコーダで1枚だけ解析する
- ライブスキャンが失敗した端末でも「写真から読む」が残る

### 2. `html/add.html` に読取UIを追加(第一優先)

- `#isbn` の近くに「バーコードを読む」ボタンを置く
- プレビュー領域(`#barcode-preview` 等)をフォーム内または直下に置く。未起動時は空または非表示
- 成功時: `#isbn` に13桁をセットし、フォーカスを戻す。自動送信はしない(誤追加防止。ご主人様が「実行」する)
- `js/barcode.js` を読み込む。既存の `settings.js` とは独立させる
- `required` の手入力はそのまま残す

### 3. `html/list.html` に同じ読取UIを追加(第二優先)

- `#q` の近くに同じボタンとプレビューを置く
- 成功時: `#q` にISBNをセットし、既存の `filterResult` を呼ぶ(検索ボタンを押さなくても絞り込む)
- `search.html` には載せない

### 4. CSS (`css/style.css`)

既存のカード・フォームに合わせ、新規classのみ追加する。

- プレビュー映像の最大幅(カード幅に収める。横はみ出し禁止)
- 読取枠の目安(細長いEAN向けに横長。正方形のQR枠は使わない)
- ライト/ダーク既存変数(`--accent` 等)を使う
- モバイル(`max-width` メディア)でボタンが押しやすいサイズにする

### 5. CGI・bin は変更しない

- `add.cgi` / `list.cgi` / `bm_search` はそのまま
- サーバーへ映像を送らない。デコードは端末内のみ

### 6. ライブラリ配置

- `js/vendor/` にライセンスファイルと本体を置く
- 外部CDNへの実行時依存は避ける
- README のファイル構成に `js/barcode.js` と vendor を追記する(実装時)

### 7. テスト

Playwright では実カメラを再現しない。次を分ける。

**自動(Playwright)**

- `normalizeIsbn` 相当の判定
  - `9784757506206` -> 採用
  - `978-4-7575-0620-6` -> ハイフン除去して採用
  - `192...`(価格コード13桁) -> 棄却
  - 12桁・文字混在 -> 棄却
- 読取成功をモックし、`#isbn` / `#q` に値が入ること
- 一覧側ではセット後に該当行だけが見えること
- 手入力・既存の追加/検索が壊れていないこと

**手動(iPhone実機・HTTPS)**

1. `add.html` を開く
2. 「バーコードを読む」をタップし、カメラ許可する
3. 背面カメラのプレビューが出る(`playsinline`、全画面に逃げない)
4. 書籍JAN(978/979)をかざし、ISBN欄に13桁が入ってカメラが止まる
5. 価格バーコードだけをかざしても入力されない
6. 「実行」で従来どおり `add.cgi` が動く
7. `list.html` でも同様に検索欄へ入り、絞り込みされる
8. 権限を拒否すると手入力が使える
9. HTTPのLAN URLでは失敗し、HTTPSでは成功することを記録する

Simulator のカメラは当てにしない。

## 画面イメージ(文言)

- ボタン: `バーコードを読む`
- 停止: `読み取りをやめる`(起動中のみ表示)
- 失敗: `カメラを利用できません。ISBNを手入力してください。`
- 価格コード等: プレビュー継続。必要なら小さく `ISBNバーコード(978/979)をかざしてください`

絵文字は使わない。既存UIの口調に合わせる。

## 注意事項

- iOS ではユーザー操作なしのカメラ起動をしない
- 成功後は必ずカメラを止める
- 映像・画像はサーバーにPOSTしない
- `search.html` は対象外
- シェル/CGIは触らない(POSIX方針の対象外)
- HTTPのまま実機で失敗しても、それはカメラ制約でありJS欠陥とは限らない。検証環境を先に確認する
- ライブラリのライセンス(Apache-2.0 等)を `js/vendor` に同梱する
- コミットは指示があるまで行わない
